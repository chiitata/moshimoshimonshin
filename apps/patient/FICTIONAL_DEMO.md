# 架空の問診デモ

必要なのは Flutter SDK のみで、Docker、Firebase Emulator、Node API は不要です。Nix も不要です。通常アプリとは別のデモ用エントリーポイント（`lib/demo_fictional_flow.dart`）から起動します。以下のサンプルだけを使い、実患者情報は入力しないでください。

## 起動

リポジトリの `apps/patient` ディレクトリで実行します。

```sh
flutter pub get
flutter run -d web-server --web-hostname=127.0.0.1 --web-port=5059 -t lib/demo_fictional_flow.dart
```

ブラウザで http://127.0.0.1:5059 を開きます。このURLは起動したマシン自身からのみアクセスできます。他の端末からこのURLでアクセスすることはできません。ポート5059が使用中の場合は、起動コマンドの `--web-port=5059` を空いているポート番号に変更し、ブラウザでも同じポートを開いてください。

## 操作

1. 「問診を始める」を押します。
2. 「架空の同意を確認しました」にチェックし、「次へ」を押します。これはデモ上の操作で、実際の同意ではありません。
3. 部位を選び（複数選択可、未選択でも可）、「次へ」を押します。選択は画面内のメモリだけに保持されます。選択肢や「次へ」が見えない場合は、画面内をスクロールしてください。
4. 症状のサンプルを確認して「次へ」を押します。患者名「サンプルさん」と症状「昨日から頭が重い」は固定内容で、編集できません。
5. 模擬送信の確認画面で架空の送信先「みほん施設」を確認し、「模擬送信する」を押します。画面に模擬完了と表示されますが、実際には送信されず、施設にも届きません。
6. 「最初からやり直す」で最初の画面に戻ります。架空の同意は解除されます。

終了するときは、起動したターミナルで **Ctrl+C** を押します。

架空の患者・施設・同意と固定サンプルだけを使う非医療デモです。実際の患者情報を入力しないでください。診断、予約、実際の同意取得や送信は行いません。デモの進行状態はアプリ内メモリに保持され、模擬送信は実施設への送信ではありません。この手順では実GCP、外部公開、実API、Dockerを使用しません。

Flutter Web の静的アセット取得やブラウザの背景通信は環境により発生し得ます。操作中を含む通信全体の包括的な観測は未実施であり、通信がないことを保証するものではありません。

正式配送 API の同意に関する問題（#219）は未解決です。架空の同意は正式な同意の代用にならず、このデモを実施設や実データに使用することはできません。
