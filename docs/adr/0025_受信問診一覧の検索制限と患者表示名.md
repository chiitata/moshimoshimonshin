# 0025. 受信問診一覧の検索制限と患者表示名の非正規化

- ステータス: 承認
- 日付: 2026-11-15
- 作成者: Devin
- 関連: docs/03_機能仕様書.md (H-003), docs/04_DB設計書.md (§5.10 deliveries), services/api, apps/hospital

## コンテキスト

H-003（受信問診一覧）は、一覧に「患者表示名・受信日時・状態・問診票ID」だけを出し、生の症状テキストを一覧段階で見せない検索制限がある。一方、既存の配送物作成処理は `patientIdentitySnapshot` を空で保存しており、一覧が患者氏名を表示する手段がなかった。また、氏名検索をクライアント側で全件取得して行う方式は、PHI を認可外の件数分だけブラウザへ送ることになり、自院スコープ・最小開示の原則に反する。

## 検討した選択肢

| 選択肢 | 概要 | 利点 | 欠点・犠牲になる点 |
|---|---|---|---|
| A | 配送作成時に同意済みプロフィールから表示名を非正規化フィールド `patientDisplayName` として保存し、一覧APIはサーバ側で `status` 等値と表示名の前方一致（範囲クエリ）を行う | 一覧が常に自院スコープ内・最小項目で完結。検索対象が明示的に同意された氏名のみに限定される | deliveries に新フィールドと複合索引の追加が必要。プロフィール更新は過去配送物へ遡及しない（スナップショットとして正しい挙動） |
| B | 一覧APIは問診スナップショットをそのまま返し、クライアント側で絞り込む | API変更不要 | 全件をブラウザへ送るため PHI の最小開示に反し、症状テキストが一覧段階で露出する。検索制限違反 |
| C | 一覧は氏名なしで提供し、詳細画面でだけ表示する | 実装最小 | H-003 の必須表示項目（患者表示名）を満たせず、未受領の判別ができない業務上の欠陥になる |
| D | 検索を別の検索基盤（外部全文検索など）へ寄せる | 部分一致・かな検索が可能 | 新しいインフラと PHI の外部移送が増え、現段階では過剰 |

## 決定

選択肢 A を採用する。

- `deliveries` に `patientDisplayName`（string?）を追加し、`POST /v1/deliveries` で `shareScope.includeProfile=true` の場合のみ `patientProfiles/{uid}` の氏名から組み立てて保存する。リクエスト本文の氏名は信頼しない（サーバがプロフィールから取得）。
- `patientIdentitySnapshot` も同意時に氏名・カナ・生年月日・電話番号だけをコピーする（フルプロフィールはコピーしない、04 §5.10）。
- `GET /v1/hospitals/{facilityId}/deliveries` は `status`（等値）と `q`（表示名の前方一致、`>= q && < q+\uf8ff`）を受け付け、施設等値を必ず併記する。検索時は orderBy を `patientDisplayName asc, deliveredAt desc` に切り替え、必要な複合索引を `firestore.indexes.json` に追加する。
- 一覧レスポンスは `senderUid` を含めない現行契約を維持し、`patientDisplayName: string | null` を追加する。未同意・旧データは `null` で「（氏名共有なし）」と表示する。
- フロントは `/api/hx/*` BFF 経由で取得し、`cache: "no-store"` を維持。フィルタ・ページング状態は施設切替でリセットされる。

## 結果・影響

- 一覧段階での生症状・全件開示を防ぎつつ、必須の患者表示名を提供できる。
- 前方一致のみ対応。部分一致・かな読み検索は本方式では扱えず、将来必要になればかな正規化フィールドの追加か外部検索の再検討（選択肢D）となる。
- 非同意配送物は氏名不明のまま一覧に出る。受領確認後の同定は詳細画面（H-004）の同意済みスナップショットで行う。
- 索引追加はデプロイ前に `firestore.indexes.json` の適用が必要（ADR-0018 の索引整合方針に従う）。
