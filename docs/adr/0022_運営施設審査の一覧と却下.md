# 0022. 運営施設審査の一覧と却下

- ステータス: 提案（本PR承認・マージをもって承認）

- 作成者: moshi_codex
- 関連: [Issue #88](https://github.com/chiitata/moshimoshimonshin/issues/88)、[ADR-0016](0016_運営管理API.md)、[機能仕様](../03_機能仕様書.md)

## コンテキスト・選択肢

承認APIはあるが、O-001に必要な運営用施設一覧・検証証跡一覧・却下APIがなかった。Firestore直読やクライアントでの状態変更は運営認可と監査を迂回するため採用しない。実BEに最小限のAPIを追加し、既存承認APIと組み合わせる。

## 決定

- 一覧はAuth/App Check＋platform_security_adminを必須にする。施設名・状態等の施設メタデータと、証跡の4検証項目・判断・日時だけを返す。非公開連絡先、審査者UID、メモ、免許番号等が入る文書参照原文を返さない。
- ページングは最大100件、createdAt降順、既存AES-GCM不透明cursor。証跡cursorは対象facilityIdとも照合する。facilityId＋createdAtの複合indexを追加する。
- 却下は再認証済み運営者のみ。pending→rejectedに限定し、receivingEnabled=false、証跡、監査を同一transactionで記録する。既にrejectedなら無変更で成功し、証跡/監査を重複させない。verified/suspendedからの却下は409とし、受付の緊急停止APIとは分ける。
- 承認は既存の4項目true＋文書参照を維持し、rejected/suspendedからの再承認も従来どおり。承認でreceivingEnabledを自動変更しない。
- 証跡にdecisionを追加する。旧承認APIだけが作成したdecision未設定の証跡はverifiedとして読む。
- ADR-0016の監査detailsにあるrecordId原文は、免許番号等を監査ログへ転送し得るためrecordRefHashへ変更する。文書参照原文は保護された証跡にだけ保持する。過去ログの削除・変更はしない。
- 画面は実一覧から施設を選択し、証跡サマリーを取得してから審査する。原本を別途確認し、明示的な確認操作を挟む。失敗時は偽の成功や自動再試行を行わず、必要なら再ログインと一覧/証跡の再取得を案内する。

## 影響・検証

新規indexを実環境で利用可能にしてから証跡一覧を公開する。indexの既存定義は削除しない。データ移行や本番患者データへのアクセスは不要。
API全体の型検査/Lint/テスト/build、実BE＋Auth/Firestore Emulator＋Chromeで承認・却下・証跡・非公開情報非露出・失効後拒否を検証する。クラウド配信/正規MFA/App Check受入は別途必要。
