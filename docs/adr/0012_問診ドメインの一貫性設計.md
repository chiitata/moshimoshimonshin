# 0012. 問診ドメインの一貫性設計（楽観ロック・分岐無効化・要約照合）

- ステータス: 承認
- 日付: 2026-11-06
- 作成者: Devin
- 関連: 04_DB設計書 §5.4, 03_機能仕様書（FR-I01〜I07, VAL-007）, ADR-0010

## コンテキスト

問診ドメインは複数端末からの並行更新・下書きの短期保存期限・回答編集による
分岐の再評価・「確認した要約」と「確定される内容」の一致性という、
一貫性上の課題を抱える。実装で採用した各機構は相互に依存するため、
設計の意図を一箇所に記録する。

## 検討した選択肢

| 選択肢 | 概要 | 利点 | 欠点・犠牲になる点 |
|---|---|---|---|
| A. revision 楽観ロック＋トランザクション分岐再評価 | intakes.revision で全書込を競合検出し、分岐変更は tx で原子的に無効化 | 矛盾した状態が永続化されない | クライアントは常に最新 revision の取得が必要 |
| B. 最終書込勝ち＋定期的な整合ジョブ | 競合を許容し後で修正 | 実装が簡単 | 問診途中の状態が一時的に矛盾し、医療安全上好ましくない |

## 決定

**A** を採用する。以下の各機構で構成する。

1. **楽観ロック**: 回答・質問追加・要約・確定のすべてが
   `expectedIntakeRevision` を要求し、不一致は `REVISION_CONFLICT`（409）
2. **期限切れの sentinel パターン**: `expiresAt` 超過を検出した tx は
   `archived` への遷移を**トランザクション内で commit** してから、
   sentinel 値を返して呼び出し側で 412 を投げる。tx 内で直接 throw
   すると Firestore がアーカイブ書込も巻き戻してしまう
3. **分岐の再評価**: 回答の上書き（`saveAnswer`/`patchAnswer`）および
   主訴変更（`submitSymptoms`）では、後続の `active`/`answered` 質問を
   `invalidated` にし、その回答を削除する。Firestore tx の
   read-before-write 規則に従い、質問一覧の読取は全 write より前に行う。
   `review` 中に無効化が起きた場合は `questioning` へ戻す
4. **出題枠の回復**: 質問数上限（12）の判定は `questionCount`（発行累積、
   `stepIndex` の供給源）ではなく non-invalidated 質問数で行い、
   無効化した分岐分だけ代替質問を発行できるようにする
   （`appendQuestion` と `generateNextQuestion` の双方で同じ規則）
5. **要約の確定照合**: `summarizeIntake` で `reviewedSummaryHash`
   （要約の sha256）を intake に保存し、`finalizeIntake` で再構成した
   要約と照合する。確認後に薬・既往歴・回答が変わった場合は 412 で
   再確認を要求する（VAL-007 の実装）

## 理由

- 問診の確定内容は医療機関へ提出される証跡。患者が「確認したもの」と
  「確定されたもの」の乖離は医療安全上許容できない
- 楽観ロックにより二端末での同時編集を衝突検出し、分岐の再評価により
  無効化した経路の回答が残存して不整合になるのを防ぐ

## 影響

- 全変更系 API は `expectedIntakeRevision` を必須とする
- 期限切れ・要約変更・revision 不一致は 412/409 で分離応答する
- 無効化質問は履歴として `questions` サブコレクションに残る
  （監査証跡として削除しない）

## 再評価条件

- 質問上限・下書き保存期間などの定数をプロダクト側で変更する場合
- 編集ではなく分岐履歴の保持（回答ごとの版管理）を要求する場合
