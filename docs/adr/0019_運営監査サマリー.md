# ADR-0019: 運営画面には監査サマリーだけを返す

- Status: Accepted
- Date: 2026-11-07
- Context: [Issue #89](https://github.com/haru-tanu/moshimoshimonshin/issues/89)、[機能仕様 O-002](../03_機能仕様書.md)、[監査ログ設計 §6](../06_医療安全_セキュリティ_運用設計書.md)

O-002には権限変更・監査イベントの監視が必要だが、既存operator APIには閲覧経路がない。監査原本には対象識別子・ハッシュ・detailsがあり、そのまま画面へ渡すとPII非表示の要件に反する。

単純な原本の一覧APIと、サーバ側で項目を限定するサマリーAPIを比較し、後者を採用する。`GET /v1/operator/audit-events` は既存Auth/App Checkゲートとplatform_security_admin認可を通す。イベント種別、操作者区分、UTC日時、認可判断、正規化結果、イベント自体のHMAC擬名IDだけを返す。未知の文字列は原文を返さずUNKNOWN/unknown/otherへ分類する。

上限100件、occurredAt降順、既存AES-GCM不透明cursorとsnapshotの位置でページングする。同時刻のイベントを飛ばさない。単一フィールドの既定インデックスを利用し、複合インデックスやデータ移行は追加しない。閲覧自体をAUDIT_EVENTS_LISTEDとして記録する。原本を直接読むFirestore client経路は追加しない。

対象別検索や個人の特定・詳細表示・一括exportは提供しない。詳細調査は権限分離された監査基盤で行う。既存の職員MFA/配信基盤の未完了部分をこの監視APIで代替しない。
