## 1\. デモの目的

**患者・施設・問診内容をすべて架空にし、外部施設連携・送信を模擬した「動くデモ」の必須縦導線を、2026-11-10 19:00（ユーザー現地時刻と仮定）までに整えること。**締切は作業目標であり、公開日・公開環境は未確定である。本書は提案段階で、承認済み要件ではない。

- 必須フロー（架空の入口 → 架空同意 → 固定症状・問診例 → 架空施設への模擬送信 → 実送信なしの結果）を審査者に動作確認してもらう。独立受信箱はP1拡張。
- 画面と手順には**架空デモであること**と、**実行されない操作**を明示する（ADR-0017）。
- 正式な規約・同意文書・契約は後日用意する。**仮の文書を正式な同意取得として扱わない**。

### 1.1 仮スケジュール（暫定・未確定）

| 段階 | 想定 | 内容 |
| :---- | :---- | :---- |
| A | 1〜2日目 | 範囲確定（§2・§3）、架空データセット準備、公開先の決定可否確認 |
| B | 2〜3日目 | P0機能の実装・調整、デモ明示（架空であること・実行されない操作）の追加 |
| C | 3〜4日目 | §4 受入条件の確認、§5 公開前安全チェック |
| D | 2026-11-10 19:00まで（ユーザー現地時刻と仮定） | 作業締切。公開判断とは別。**§5 に未了の重要確認があれば公開しない** |

期間が不足する場合は §3 の優先度で対象を見直し、対応する受入条件も同時に更新する。未実装を実装済みと見せず、§5 の公開前安全チェックは省略しない。

### 1.2 目的でないこと

- 実患者データ・実施設の非公開情報の取り扱い、実施設への実配送・実受領
- 診断・治療・受診予約・実通知の送信
- 正式な法務文書、医療機関契約、パイロット運用
- 旧版 §9 のリリースゲート **G0〜G5 の充足**、本番SLO/DR（旧版 NFR-07 / NFR-10）の達成
- 正式運用向けKPI（旧版 §1.4）の計測

## 2\. 対象 / 対象外

| 区分 | 内容 | 扱い |
| :---- | :---- | :---- |
| 対象（架空データ） | 架空患者アカウント・プロフィール・問診票・薬剤・身体図・回答・確定票 | シードまたは利用者が用意した架空データのみ |
| 対象（架空施設） | 架空の医療機関、架空職員アカウント、架空の受信箱 | 実在施設を受信先にしない |
| **模擬** | 外部施設連携・配送、通知配信、および外部APIを使う処理（施設検索・LLM・OCR） | 実施設向け連携・実配送・実通知・これらの実外部 API 呼び出しは行わない。画面・操作の範囲は §3 を参照 |
| 明示必須 | 「架空デモであること」「実行されない操作」の表示 | 主要画面と手順で確認できるものとする（ADR-0017） |
| 後日（正式運用） | 正式な規約・同意文書、医療機関契約と施設真正性確認、退会・法定削除の実対応、監視・バックアップ・SLO | 正式運用の必須要件として旧版に維持。**デモの完了条件にはしない** |
| 対象外 | 実データ、実通知、診断・治療・予約確定、病名確率、薬の服用・中止指示、決済、遠隔診療ビデオ | 旧版 §0・§2 の境界をそのまま維持 |

補足（旧版からの維持事項）：Google Places に載っているだけで受信先にはしない（旧版 BR-11）。非参加・架空以外の施設は「送信不可」表示とする（旧版 FR-H03）。

## 3\. 機能優先度（デモ）

優先度は **P0：デモ必須／P1：余裕があれば／後日：正式運用で必須・デモ非適用** の3段階。IDは旧版のまま。

### 3.1 P0（4日で作る必須デモ縦導線）

入口（架空デモである旨）→架空同意（正式同意ではない旨）→固定症状・問診例→架空施設への模擬送信→実送信なしの結果、を一本の導線として確認可能にする。実患者登録・実サービス連携・実送信は含まない。以下の表はこの導線に必要な最小範囲に限定する。

| 旧版ID | 機能 | デモでの扱い |
| :---- | :---- | :---- |
| （本版追加） | 架空の入口・同意 | 架空デモの入口から仮同意の表示まで。アカウント作成・実認証を必須にしない。正式同意として扱わない |
| FR-I01 〜 FR-I05, FR-I07, FR-I08, FR-I10 | 固定症状・問診例 | 固定の架空症状・問診例で確認から確定まで進める。実AI不要。「戻る」「スキップ」「分からない」は導線に含める範囲で実装 |
| FR-I09, FR-I11, NFR-04 | 安全制御 | 疾患候補・診断確率・処方提案・受診不要判定・予約確定を**表示しない**。未監修の医療・緊急案内を追加せず、推測値を事実として補完しない |
| FR-I10 | LLM停止時の代替 | 固定質問のみで問診を完了できる（外部LLM不使用でも成立させる） |
| FR-H03, FR-H05〜FR-H08 相当 | 模擬送信・結果 | **固定の架空施設**への操作を模擬し、実送信なしの結果を示す。施設検索・一覧からの選択はP1。多重操作で重複表示せず、実配送ではない旨を明示 |
| （本版追加） | デモ明示 | 主要画面に「架空デモ」「実行されない操作」を表示（ADR-0017）。IDは新規採番せず要件文として扱う |

### 3.2 P1（余裕があればの拡張・必須導線に含めない）

| 旧版ID | 機能 | デモでの扱い |
| :---- | :---- | :---- |
| FR-M01 〜 FR-M04 | 薬画像アップロード・OCR・候補・人手確認 | **架空画像のみ**を使用し、実写の処方箋を入力させない。OCR未実装なら架空の候補提示に差し替え可 |
| FR-H01, FR-H02 | 現在地・施設検索・選択 | 実のPlaces APIは呼び出さず、必要なら**架空施設の一覧**を用いる（§7 D-Q02・D-Q06）。P0の固定施設への模擬送信に施設検索は不要 |
| FR-A11, FR-A12 | 退会・期限到来削除 | 画面確認のみ。**実際の削除は行わない**（後日） |
| FR-A04 | Passkey | 本人確認・復旧・実装の承認が整うまで非表示・無効。デモの完成条件にしない |
| FR-O04 | 管理者運用画面 | 障害一覧など PII が表示されないこと |
| FR-A01, FR-A02 の実アカウント化 | 架空ログイン | 架空認証を追加する場合のみ。実メールは送信しない |
| FR-I06 | 永続的な問診中断・再開 | セッションをまたぐ永続的再開 |
| FR-H09, FR-H10 | 独立受信箱 | 病院側の独立受信箱・架空職員による閲覧／受領確認 |

補足（P1同士の関係）：施設検索（FR-H01・FR-H02）と病院側独立受信箱（FR-H09・FR-H10）は、いずれも**独立した追加候補**であり、片方の成立が他方の前提にならない。両機能を連携させるか否かは**未決定**。P0の固定架空施設への模擬送信は本補足で変更しない。

### 3.3 後日（正式運用で必須・デモでは扱わない）

| 旧版ID | 機能 | 備考 |
| :---- | :---- | :---- |
| FR-A03, FR-A05, FR-A06 | Google連携・アカウント統合・パスワード再設定の完全形 | 正式運用 |
| FR-H04 | 施設真正性の運営検証 | 架空施設のためデモでは実施しない。**正式運用の必須要件であることは変わらない** |
| FR-H11, FR-H12 | 職員管理・MFA・送信後の再送 | 正式運用 |
| FR-O05, FR-O06 | 実通知配信・Sentry | 実通知は行わない |
| NFR-07, NFR-10, NFR-15 | 可用性SLO・復旧・規制ギャップ分析 | デモ非適用 |
| 旧版 G0 〜 G5 | リリースゲート | デモの完了条件にしない（§6） |

表にない旧版 ID はデモ必須と推定せず、必要になった時点で対象・優先度を決める。旧版の定義は保存版に残す。

## 4\. 受入条件（デモ）

以下は**達成すべき基準**であり、本版の作成時点で**検証済み・達成済みとは断定しない**。検証は公開前に実施し、結果は公開判断の記録として残す（本ファイルには検証結果を書き込まない）。

| ID | 受入条件 |
| :---- | :---- |
| AC-D01 | 架空デモの入口から架空同意の表示へ進める。仮文書・デモ用である旨を表示し、正式な同意取得・実認証として扱わない |
| AC-D02 | 固定の架空症状・問診例を用いて、確認から模擬送信操作までの必須縦導線を完走できる。実AI・自由入力・身体図は必須でない |
| AC-D03 | 永続的な中断再開はP1拡張であり、必須受入条件としない |
| AC-D04 | どの画面でも疾患候補・診断確率・処方指示・受診不要判定・予約確定や未監修の医療・緊急案内が表示されない（旧版 FR-I09 / NFR-04） |
| AC-D05 | 送信操作の前後で「架空デモのため実施設へ送信されない」ことを確認でき、実施設・実在個人へデータが到達しない |
| AC-D06 | 独立受信箱・架空職員による受領確認はP1拡張であり、必須受入条件としない。実送信なしの結果を確認できる |
| AC-D07 | 初期状態・シードに実在を疑わせる実データが含まれず、画面・URL・通知に実データが露出しない |
| AC-D08 | 主要画面と手順に、架空デモであること・実行されない操作が明示されている（ADR-0017） |
| AC-D09 | §5 の公開前安全チェック全項目が確認済みで、結果と未解決事項が記録されている。**重要な確認が未了なら公開しない** |
| AC-D10 | 公開範囲に応じたアクセス制限が設定されている。検索除外設定だけをアクセス制限の代替にしていない |
