# 患者画面のローカルプレビュー

以下は作成時点で確認した独立プレビュー用エントリポイント8個と画面実装の例です。全エントリポイントを網羅した一覧ではありません。各プレビューは `MaterialApp` から対象画面を直接表示し、Firebase/API/実送信の初期化・接続をしていません。通常の患者アプリ準備画面は `main.dart` から起動し、Firebase Emulator の初期化を行います。合成データ以外（実患者情報・実在施設の非公開情報）は使わないでください。

Firefox headless の起動と semantics による操作確認は、別の `demo-fictional-patient-flow` worktree 版で実施しました。この文書の対象 worktree 版そのものを検証した結果ではありません。

## 独立プレビューの起動方法（Docker・Firebase なし）

Flutter SDK と Firefox 等のブラウザを用意します。flake のキャッシュ済み開発環境があれば、リポジトリルートで `nix --offline develop` に入れます（このコマンドは当環境で Flutter SDK を表示できることまで確認済み）。その後、以下をリポジトリルートから実行します。Docker、Firebase Emulator、API の起動や Firebase の設定は不要です。

```bash
cd apps/patient
flutter pub get
flutter run -d web-server --web-hostname=127.0.0.1 --web-port=5050 -t lib/demo_body_location_preview.dart
```

起動後、同じ PC のブラウザで <http://127.0.0.1:5050> を開きます。ポートが使用中なら `--web-port=5051` のように変更し、URL も合わせてください。終了は Flutter のターミナルで `q` または Ctrl+C です。この独立エントリポイントは Firebase 初期化を行いません。`make up` は Docker 等も起動するため、この手順では使いません。

下表は作成時点で確認した独立プレビュー用エントリポイント8個の対象例であり、患者アプリの全エントリポイント一覧ではありません。表の各エントリポイントはすべて `apps/patient` を作業ディレクトリにして `flutter run -d web-server --web-hostname=127.0.0.1 --web-port=5050 -t <表の固定パス>` の `<表の固定パス>` に指定して起動します。任意の Dart ファイルや `main.dart` に置き換えず、表にある `lib/demo_*_preview.dart` のみを対象にしてください。通常の患者アプリを確認する場合は [`apps/patient/README.md`](../apps/patient/README.md) の手順を参照してください。`main.dart` は Firebase Emulator 設定を使って初期化するため、この Firebase 不要の手順には含めません。通常アプリや画面をまたぐ一連フローの確認は、それぞれの手順に従ってください。

コード上で独立起動を確認できるのは上記の表示例までです。実際の認証、同意保存、問診保存/OCR、配送および実際に発生した失敗状態は未接続または未確認です。これは実データ向けでも公開前提のものでもなく、これらのプレビューを実データで試さないでください。

`flutter pub get` や Flutter Web のアセット取得には通信が発生する場合があります。患者データを入力・送信しないことと、通信が一切ないことは別です。環境によっては依存関係の事前取得や Flutter SDK の Web 対応が必要です。

## 確認すること

- 別 worktree 版を Firefox headless + semantics で確認し、頭と首の複数選択、頭の解除、「わからない」の排他選択と解除、「次へ」が無効であることを確認しました。これは Issue #118 全体の完了を意味しません。
- 狭い画面、ブラウザ拡大、Tab / Space 操作、再読み込み、実際の支援技術による確認は未実施です。ブラウザの背景通信も監視していません。

## 限界と別環境

Issue #118 の受入条件にある主要画面の表示例は上表に整理しましたが、実際に発生した失敗状態は未確認です。配送の「失敗」は架空サンプルであり、実失敗を再現・確認したものではありません。認証未接続や OCR 処理中表示も失敗ではありません。したがって失敗状態の受入確認は未達です。Web の表示や操作は Android / iOS と同一ではなく、実ブラウザおよび Android での動作確認、実機や正式なアクセシビリティ受入は未実施です。Android には別途 SDK、Emulator、システムイメージと仮想化環境が必要です。`flake.nix` には Flutter が含まれますが Android SDK / Emulator は含まれません。Nix での導入、KVM の権限、必要なディスク・メモリ、および Web との差異は未検証です。iOS のビルド・シミュレータには macOS と Xcode が必要です。
